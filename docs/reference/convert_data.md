# The unit database `convert()` reads

One entry per database – only `base` exists – holding one `2 x n` array
per dimension of measure: `Energy`, `Power`, `Mass`, `Time`, `Length`,
`Area`, `Pressure`, `Density`, `Volume`, `Flow Rates` and `Currency`.
The columns are unit spellings and the rows are `coef`, the factor to
that dimension's base unit (its first column, which is 1 by
construction), and `SI_prefixes`, whether a prefix may be attached.

## Usage

``` r
convert_data
```

## Format

A list of one database, each a named list of `2 x n` numeric arrays with
row names `coef` and `SI_prefixes`.

## Details

Two dimensions of measure are not alike here. The physical ones are
fixed ratios and are maintained by hand. `Currency` is not: an exchange
rate is a measurement with a date, so its `coef` row is GENERATED by
`data-raw/currency.R` from
[currency_fx](https://energyRt.org/reference/currency_fx.md) at
`attr(currency_fx, "base_year")` and the column order is
[currency_codes](https://energyRt.org/reference/currency_codes.md)`$spelling`.
Dated conversions do not read this row at all beyond dividing it out –
see [`convert()`](https://energyRt.org/reference/convert.md).

A conversion resolves a spelling by scanning the dimensions and then the
columns, and the first match wins, so column order is load-bearing and
[`add_to_convert()`](https://energyRt.org/reference/convert.md) appends
rather than inserts.

## See also

[`convert()`](https://energyRt.org/reference/convert.md),
[currency_codes](https://energyRt.org/reference/currency_codes.md),

## Examples

``` r
names(convert_data$base)
#>  [1] "Energy"     "Power"      "Mass"       "Time"       "Length"    
#>  [6] "Area"       "Pressure"   "Density"    "Volume"     "Flow Rates"
#> [11] "Currency"  
convert_data$base$Mass[, 1:4]
#>             t     g metric tonne US short ton
#> coef        1 1e-06            1        0.907
#> SI_prefixes 1 1e+00            1        1.000
convert_data$base$Currency[, 1:4]
#>             USD cents mills      RMB
#> coef          1  0.01 0.001 0.139085
#> SI_prefixes   1  0.00 0.000 1.000000
```
