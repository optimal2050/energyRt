# energyRt testing guide

> Recipes and traps. For *why* the suite is built this way -- and what it
> deliberately does not test -- see the **Testing strategy** article
> (`vignettes/articles/testing.Rmd`). For the `@covers` tag grammar and the
> tier table, see `tests/README.md`.

The testing system is organized around a generated **coverage matrix**
(`tests/coverage/parameter-matrix.csv` + `matrix-summary.md`, regenerated by
`tools/coverage/build_matrix.R`): every numeric parameter, map, equation, and
variable of the model is a row, with its `class@slot$column` provenance, its
feature family, and its current test coverage. Coverage is declared by
structured `# @covers` tags in test files (convention: `tests/README.md`) and
validated by the same tool (`--check`, wired into `test-coverage-matrix.R` —
a typo in a tag name fails the suite). The full planning inventory lives in
`dev/coverage-inventory.md`.

Companion machinery:

| Piece | Where | What it gives you |
|---|---|---|
| Tier system | `tests/testthat/helper-solvers.R` | `ENERGYRT_TEST_TIER`: `check < fast < cross < nightly`; per-backend skip guards |
| Fork harness | `tests/testthat/helper-forks.R` | `run_family()`: interp-mode invariance, cross-backend parity, invariants per solved cell |
| Invariant checker | `R/verify_solution.R` (exported) | balance / totals / cost / objective identities on any solved scenario |
| Goldens | `tests/testthat/helper-goldens.R`, `tools/test/make_goldens.R` | tracked-value benchmarks, capture gated by the invariants |
| Reference models | `tests/testthat/fixtures/testing-models.R` (tm_* tiers), `helper-topia.R` (TOPIA kits) | deterministic solve fixtures |
| Interp goldens | `tools/test/interp_guard.R`, `tests/testthat/goldens/interp/` | tracked modInp baselines diffed with `compare_inputs()` (nightly) |
| Runners | `tools/test/run_fast.R`, `run_cross.R`, `run_nightly.R` | tier runs with a summary line and non-zero exit on failure; nightly writes a markdown report |

## 1. Adding a test for a new parameter

When a new entry lands in `data-raw/modInp.yml` (and sysdata is regenerated):

1. Run `Rscript tools/coverage/build_matrix.R` — the new row appears with
   `covered_depth=none`. No hand-editing: the matrix is always regenerated.
2. Pick the feature-family test file (`family` column) or create
   `test-family-<family>.R`.
3. Write a mini-model in which the parameter has an **analytically predictable
   effect** on the objective or flows, and drive it through the
   `run_family()` fork harness (worked examples:
   `test-family-import-export.R`, `test-family-tech-availability.R`).
   The harness runs every interp case (default/dense/folded/ondisk) at depth I,
   solves them all with GLPK asserting interp-mode invariance, solves other
   backends at tier cross asserting objective parity, and runs
   `verify_solution()` on every solved cell. Family files add analytic
   assertions via `check_params(scen, case)` / `check_solution(scen, backend,
   case)` and the accessors `ff_param()` / `ff_bound()` /
   `ff_solution_sum()`. Standalone (non-harness) cases in a family file reuse
   `.fork_solve()` / `.fork_objective()`.
4. Climb the depth ladder as far as the parameter warrants:
   - **C** — constructor round-trip: the value survives `newTechnology()` etc.
   - **I** — after `interpolate_model()`, the value lands in the right
     `modInp@parameters[[...]]` slice with the right dims (solver-free; this
     alone is the minimum bar for "the parameter has a test").
   - **S** — a GLPK solve shows the predicted effect.
   - **X** — the same on 2+ backends.
5. Tag the test block with
   `# @covers <names> depth=<C|I|S|X> backends=<...> forks=<...>` and
   regenerate the matrix; commit the CSV/summary diff together with the test —
   the summary diff is the review artifact.

**When a test exposes a defect** (this project found ten): report it, and pin
the current broken behavior with a labelled **KNOWN-BUG expectation** so the
eventual fix fails loudly and the pin is replaced by the real assertion.
Worked life cycle: the ramp limits were pinned inert, then fixed (catalog
provenance + wildcard join + two template defects), and the pins became the
analytic ramp tests in `test-family-tech-availability.R`. A deliberate design
decision discovered along the way is documented and *tested as intended
behavior* instead (e.g. a lone `inp2out.up` leaving the charger floor open).

## 2. Adding a test for a new variable or equation

- Declare the variable's `role` (`source`/`sink`/`interregional`/`activity`/
  `balance`/`stock`/`capacity`/`cost`) in `data-raw/variables.yml`. Roles feed
  the generic solution invariants (`verify_solution()`):
  a `cost` role enters the cost-decomposition identity automatically (the
  overnight-investment reporting variables `vTechInv`/`vStorageInv`/`vTradeInv`
  are the deliberate exceptions — the objective carries the annualized `*Eac`).
  A wrong role makes invariants fail on every solved model — that is by design.
- `verify_solution()` replicates template identities as map-driven data joins:
  `eqBal`, `eqBalLo/Up/Fx`, `eqOutTot`/`eqInpTot` (incl. timeslice-family and
  region-family roll-ups), `eqCost`, `eqObjective`. Every solved fixture in the
  suite should pass it; new checks extend `.vs_check_*` in the same style.
  Conventions the checker relies on: missing solution rows mean **0** (solvers
  export non-zeros only); missing parameter rows mean the parameter's
  **defVal** (sparse interpolation drops default-valued rows).
- If new maps gate the equation, extend the mapping-engine snapshot
  (`test-mapping-engine.R`) and tag the map/equation names.
- A new equation must guard every variable reference against that variable's
  declared domain on ALL four backends — GMPL and JuMP tolerate an
  out-of-domain reference in ways Pyomo does not, and an unguarded term is
  either a Pyomo crash or a stray free variable (precedent: the phaseout
  equations' `vTechNewCap` term, fixed 2026-08-25).

## 3. Adding a test for a user constraint or cost term

- Build with `newConstraint()` (summand fields: `variable`, `mult`, `for.sum`,
  `defVal`, `timeframe`, `geoframe` — an unknown field is an **error**, e.g.
  `tech = "X"` must be `for.sum = list(tech = "X")`) or `newCosts()`
  (`variable` with region+year dims, scalar or set-indexed `mult`, optional
  `subset`).
- Assert both the compiled equation (the IR in `modInp@gams.equation` /
  `modInp@costs.equation`, see `test-user-constraint.R`) and the solved effect
  on the objective (worked example: `test-family-constraints-costs.R` — a
  per-tech capacity cap forcing the merit order, and cost terms entering via
  `eqTotalUserCosts` / `vTotalUserCosts`).

## 4. Regenerating benchmarks (goldens)

Goldens are tracked JSON in `tests/testthat/goldens/` storing the objective
plus tracked variables at two aggregation levels (annual×region and
annual×total; per-timeslice values are deliberately not stored — degenerate
optima make them solver-specific). Tolerances live in
`tests/testthat/helper-goldens.R` (`TOL_SAME_SOLVER` 1e-9,
`TOL_XSOLVER_OBJ` 1e-6, `TOL_XSOLVER_AGG` 1e-5).

1. Only regenerate when a behavior change is **intended**.
2. `Rscript tools/test/make_goldens.R
   --suite=<tm|topia|topia_nightly|unit|interp|all> [--dry-run]` — prints
   an old-vs-new diff and **refuses** to freeze a baseline that fails
   `verify_solution()`. The `unit` suite pins the all-unit-input kits
   (`topia_modules$unit`) whose objectives are small integers computed BY
   HAND in `data-raw/topia_modules.R` and asserted analytically by
   `test-unit-model.R` — if a unit golden moves, re-do the arithmetic before
   even thinking about refreezing. Each suite has a REFERENCE SOLVER
   (`SUITE_SOLVERS` in `make_goldens.R`), following the backend-choice
   convention — glpsol for small models, julia/HiGHS for mid-size and
   sampled ones (expected solve over ~30 s: startup no longer dominates and
   HiGHS's presolve/dual simplex win). `topia_nightly` (R7/R11) references
   `julia_highs`; same-solver goldens are captured and compared with the
   suite's solver, so regenerating those needs Julia + JuMP/HiGHS. The `interp` suite is different in kind: solver-free
   **modInp baselines** (`goldens/interp/<tier>.rds`, xz, tracked in git but
   Rbuildignored), frozen by `tools/test/interp_guard.R baseline` and checked
   by `interp_guard.R check` / `test-interp-golden.R` (nightly tier) with
   `compare_inputs()`. They pin what interpolation HANDS the optimizer, so a
   representation change that still solves to the same objective fails there
   instead of slipping through the solved goldens.
3. Commit the regenerated goldens **in the same commit** as the code change,
   with a NEWS bullet. Never edit golden JSON by hand.
4. Tests compare with `expect_matches_golden(scen, suite, entry, kind =
   "same_solver" | "cross_solver")`; a missing golden skips with the capture
   command in the message.
5. A template change that leaves objectives identical can still move
   same-solver tracked values: removing or adding any variable changes the LP,
   and the solver may land on a different equal-cost vertex. That is a
   legitimate rebaseline (same commit, NEWS) — the `--dry-run` objective diff
   tells you which kind you have.

Roll-up convention pinned by `test-getdata-rollup.R`: `timeframe="lowest"`
equals the **plain sum** of `timeframe="highest"` (weight-invariant, also on
sampled calendars); annualization by `pTimesliceWeight` is a cost-layer
concern, not a reporting default.

## 5. Adding a new reference model

Entry requirements, all satisfied by the current suites (tm_* tiers,
TOPIA kits):

- **deterministic inputs** (no RNG; TOPIA ships curated profiles);
- documented **size and runtime**, and a **tier assignment** that matches it
  (tm_* seconds → fast; TOPIA R1/R3 × `topia_s4h24` seconds → fast;
  R7/R11 and `topia_m12h24` → nightly);
- **goldens captured** via a `make_goldens.R` suite entry (which enforces the
  invariants) and a test comparing with `expect_matches_golden()`;
- **cross-solver cells declared or explicitly excluded** — an exclusion is an
  asserted error or a documented skip, never silence (e.g. GAMS unlicensed →
  skip with reason; GAMS × sparse → the writer's density error).

TOPIA specifics (`helper-topia.R`): every layout kit targets
`topia_s4h24` — ELC lives at the HOUR level, so coarser calendars are
incompatible with the shipped repos. Levers are objects added with `add()`;
on the R1 layout only the carbon tax shifts the base objective — the other
four levers are non-binding there and the goldens pin exactly that.

**What is comparable across solvers** (measured, not assumed): alternative
optima make even annual, entity-collapsed totals solver-dependent — tm_core
produces 65 (GLPK) vs 58 (HiGHS) at the *identical* objective because trade
and storage substitute freely. Cross-solver parity therefore compares only
the objective, the accounting invariants, and constraint-pinned quantities
(demand served); see `test-cross-solver.R`.

## 6. Running the tiers

Tier resolution lives in `tests/testthat/helper-solvers.R`
(`ENERGYRT_TEST_TIER`, `check < fast < cross < nightly`; unset → `check` under
R CMD check, `fast` otherwise — the old `skip_on_cran()` silent-skip trap is
gone, a bare `Rscript` run now solves whenever glpsol is present).

```powershell
devtools::check()                          # tier check (solver-free, auto-detected)
devtools::test()                           # tier fast (glpsol)
Rscript tools/test/run_fast.R              # tier fast, summary + exit code
Rscript tools/test/run_cross.R             # tier cross, availability table first
Rscript tools/test/run_nightly.R           # tier nightly: full suite + interp
                                           #   goldens; report in tmp/test-reports/
Rscript tools/coverage/build_matrix.R --check   # tag validation
Rscript tools/test/make_goldens.R --suite=tm    # deliberate rebaseline
```

Backend guards: `skip_if_no_solver()` (glpsol, tier fast),
`skip_if_no_julia_highs()` / `skip_if_no_pyomo()` / `skip_if_no_gams()` (tier
cross; the GAMS guard also skips an unlicensed install — no `gamslice.txt`
next to the executable) and `skip_if_no_neos()` (additionally requires
`ENERGYRT_TEST_NEOS=true`).

The nightly tier adds: the interp goldens (`test-interp-golden.R`), the
TOPIA R7/R11 goldens plus an R3 julia/HiGHS parity check
(`test-nightly-deep.R`), and external real-world models — opt-in via
`ENERGYRT_EXT_MODELS=<dir>` (the useR2026 course models), each loaded
through the serialization upgrade path, solved on julia/HiGHS, and gated by
`verify_solution()`; the full-year copperplate and the 41-node European
model additionally need `ENERGYRT_TEST_HEAVY=true`. See `tests/README.md`
for the Task Scheduler one-liner and the GitHub Actions sketch.

**Known blind spot of `verify_solution()`** (candidate hardening): it
replicates the equations FROM THE SAME MAPS the writers use, so a
missing-domain bug — a map that silently dropped a cell, leaving a
declared-over-the-full-cross-product variable free and costless in GLPK —
verifies clean (the coarse-supply bug of 2026-08 solved to objective 0 with
invariants "ok"). A structural audit would close the class: every
`mvBalance` cell must be reachable by at least one producer-or-consumer map
row, else warn. Until built, hand-computed objective pins (the unit kits,
the nested-regions hand values) are the only guard that catches it.

## 7. Traps (each learned the hard way)

- **Folded wildcards**: mid-pipeline, parameter data can still carry all-NA
  wildcard dimensions. A plain join against an explicit-membered domain
  matches nothing and silently empties a map — drop fully-NA columns first
  (house pattern; bit the ramp maps and the structural ratio maps).
- **Bounds are stored unexpanded** in `modInp` — one parameter with a
  `type` column (`lo`/`up`/`fx`), not `...Lo`/`...Up` pairs. Use `ff_bound()`.
- **Storage part capacities are power rates**: flow bounds read
  `cap * cap2act * share * af` and `cap2act` defaults to **8760** — pin
  `cap2act = 1` in tests that want readable arithmetic.
- **Weather multiplies the af bound**; `af.lo` defaults to 0, so a must-run
  profile needs `af.fx` alongside `waf.fx`.
- **A lossless free storage plus an output subsidy is an unbounded money
  pump** — subsidy models must exclude it.
- An **unused commodity is pruned** from the balance entirely; limtype tests
  need the commodity supplied and demanded.
- **Solve success**: check `status$solved` / `status$optimal` (set at solution
  read) or the presence of `vObjective`. An infeasible or unbounded model is
  reported, not thrown: `solve_scenario()` warns with the solver's own verdict
  and returns a scenario whose objective reads `NA`. Only missing output with
  NO verdict still errors -- that is a solver that never ran.
- Standalone `testthat::test_file()` needs `pkgload::load_all(".")` first
  (setup files call package functions unqualified; the installed copy may be
  stale versus the source tree).
- Concurrent test processes are **safe since 2026-09-28**: every process gets
  its own scenarios root under its own `tempdir()`
  (`tests/testthat/setup-registry.R`). Scenario names are deterministic per
  test (`ff_<family>_<case>`, `st_<tier>`) and the fork helpers pass
  `overwrite = TRUE`, so before that fix two processes silently overwrote
  each other mid-solve — the old "phantom failures". The one remaining way
  to collide is to point two processes at the **same**
  `ENERGYRT_TEST_SCENARIOS` pin: one pin, one process.
- PowerShell one-liners eat `$glpk` inside double quotes
  (`solver_options$glpk` becomes `solver_options`) — put R code in a script
  file.
- Editing a solver template or any `data-raw/*.yml` has no effect until
  `data-raw/DATASET.R` regenerates `R/sysdata.rda`; `data-raw/maps.R` is
  gams2x-generated from the GAMS source and hand-edits must follow its format.

## 8. Time-discretization invariance suites

`test-multiyear-invariance.R` + `test-sampling-invariance.R`
(fixtures in `helper-invariance.R`) pin the contract that the same physical
problem yields the same undiscounted totals regardless of how time is
discretized. All parameters are small integers and `discount = 0`, so every
expected value is exact arithmetic and a granularity-dependent factor fails
by an integer ratio that names its own cause.

- **Multi-year** (green): identical totals at 1-, 5- and 10-year milestones
  for varom, fuel, fixom, stock, capital (eac and invcost routes), the
  per-year `ncap.up` rate contract, and annual CO2 caps. Rate convention
  pinned: `v*NewCap` is an annual build rate; standing capacity and all
  per-unit-standing charges accumulate `pPeriodLen * v*NewCap`.
- **Sampling** (all green since the annualized-ANNUAL convention landed):
  per-slice variables are RAW (identical between full and sampled
  calendars); the top slice is full-year magnitude (`share = weight = 1`);
  every fine -> coarse aggregation carries `pTimesliceAgg` (the
  child/parent weight ratio — 1 everywhere except `1/year_fraction` into
  the top slice); each commodity has total cells at every ancestor level
  (fed by the roll-up chain ONLY — component `*Tot` terms feed the
  commodity's own level, never a parent cell, or the flow double-counts);
  with a geoscale, also at every ancestor REGION level (plain extensive
  sums, and the region term fires only at the commodity's own timeslice —
  the canonical single path through the level x timeframe lattice);
  balances stay at the commodity's own level on both axes. Aggregation
  only, never disaggregation. Interpolation refuses old-convention sampled
  calendars (top share == year_fraction).
